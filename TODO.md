# TODO / Ideas

- **Waveform live re-coloring on theme toggle.** `WaveformTrimmer` reads the resolved `--mat-sys-*` colors once, when a file loads (`getComputedStyle` at wavesurfer creation time). If the Material theme's light/dark mode changes while a waveform is already rendered, its colors stay as they were until a new file is loaded. Not a spec requirement — just noted in case it's ever visibly jarring.
- **Tap tempo: alternative "wait for pause, then compute" mode.** Built version updates the BPM field live after every tap (from the 2nd tap onward, sliding window of the last 8 intervals, resets after a 2s gap). Considered alternative, explicitly deferred by the user: don't touch the BPM field at all until the user stops tapping for ~1.5s, then compute and apply the final average in one shot. Would trade away the live feedback for a single, less jumpy final value — worth trying if the live-update version feels twitchy in practice.
- **Integrating into `the-chords` later needs two things added there, not here:** (1) the Material Symbols Outlined + Roboto font `<link>` tags (currently only in this repo's own `demo-count-in-practice/src/index.html`) need adding to `the-chords/src/index.html`, or `mat-icon` will render literal text instead of glyphs; (2) `provideAnimationsAsync()` (from `@angular/platform-browser/animations/async`) needs adding to `the-chords`' own `app.config.ts` providers, or Material's ripples/transitions won't run.
- **Material theme is intentionally scoped to `:host` of `<the-chords-count-in-practice>`** (`count-in-practice.scss`, `mat.theme(...)` seeded from `_theme-colors.scss`, generated via `ng generate @angular/material:m3-theme` from the neon brand colors), not applied globally — so it won't leak Material's `--mat-sys-*` tokens onto the rest of `the-chords` when embedded. This was a deliberate call, not yet confirmed with the user for the eventual full-suite Material migration they mentioned wanting to start elsewhere.
